# Developer exposure checklist

Required for every feasible new or changed gameplay feature in this preview and future AXIOM work:

- [ ] Name the actual system and state owner; use the game’s terminology. Do not invent XP when progression is materials, renown or stewardship.
- [ ] Add supported values to a typed registry with defaults, units, finite bounds, description, real consumer and effect timing (apply, reset, regenerate). Test low/default/high outcomes. A slider with no gameplay consumer is a defect.
- [ ] Keep pending edits distinct from applied values. Provide readable numeric entry, keyboard/touch-sized controls, per-section and whole-setting reset, cancel/discard, and an honest applied-state message.
- [ ] Put the player near an actual test through a reproducible seed/scenario, real isolated spawn/reset and useful equipment. Clearly distinguish playable practice, disposable model simulation and read-only inspection.
- [ ] Define isolation first. No ordinary slot writes, reward grants, world mutation, background catch-up or room divergence from local tuning. Show sandbox status and a reversible exit. Shared games require supported authoritative settings; otherwise disable with a solo-only explanation.
- [ ] Version changed replay inputs. Never mutate module-level rule constants at import time. Save validators, resource conservation, generation manifests, authoritative workers and renderers must agree. Keep historical defaults and reports compatible, or reject unsupported versions clearly.
- [ ] Export build/source, seed, intended and actual scenario, applied values, mode, bounded actions and relevant evidence. Include enough context to reproduce. Exclude credentials, room tokens and campaign data unless specifically required and authorized.
- [ ] Import through strict allowlists, versions, finite ranges and size limits. Stage imported data for explicit Apply/reset. Reject unknown fields and scripts. Guard asynchronous reads against navigation/replacement. Keep a text fallback for clipboard/download failures.
- [ ] Test reset, repeated actions, cancel/close, import/export round-trip, stale asynchronous results, reload, normal-slot invariance and shared-world gates. Verify source and emitted worker behavior where affected.
- [ ] Update the coverage inventory below and in-game entry points. Report browser/device checks separately from numerical and DOM-contract checks.

## Presets and restoration

Developer lab uses registry version 2 and a strict 24 KB portable preset. Device storage is explicit, under the existing experimental-preview namespace; previous v1 presets are not silently upgraded or loaded. A preset seed records provenance and never switches or overwrites a world. If imported into another seed, the UI states the mismatch; the course geometry remains fixed, but the sentry appearance uses the current seed.

The intended setup is distinct from the actual running station. Selecting a station does not move the player until Reset & practice. The feedback report records both. Closing the panel discards unapplied draft edits. Sentry attempts keep their latched settings. The previous v1 sentry trace format is normalized during comparison when its optional new damage field is absent.

Return to campaign restores the captured campaign state, pose and combat. Reloading the page returns to the last normal saved checkpoint. No sandbox is written to the normal slot.

## Startup diagnostics

The inline HTML shell owns startup state, deadlines, redaction, cancel/reload and the report before the game bundle or CSS runs. `src/startup.ts` is its typed contract and the allowlisted scenario registry. Main owns gameplay readiness; Rapier receives `startPaused` in its initial packet and cannot advance until the first post-ready input. Saved waterworks / cave-flood collision is part of the initial packet. Spawn recovery, nearby chunks, current equipment, creature pose, lighting, cutaways and materials are projected without world ticks.

Reports → Startup diagnostics offers read-only report viewing and an explicit next-navigation test. Each test explains its effect, applies only after Reload, and is removed from the URL immediately. No arbitrary code, imported fault settings, timeout sliders, remote report upload or campaign payload export is accepted. The existing explicit save-recovery archive remains separate from sanitized diagnostics.

Critical budgets: module fetch/evaluation 60 s, bounded plan preparation 10 s (existing speculative work budget 1.5 s), session validation 10 s, scene creation 30 s, nearby generation 60 s, Rapier initialization 30 s, renderer selection 30 s, compilation 45 s, first frame submission 15 s. Synchronous over-budget completion is rejected once the event loop returns. A hung browser thread or missing HTML cannot render its own diagnostic. Optional remote fonts have a 1.8 s internal / 2 s outer deadline and system-font fallback. Audio requires a later player gesture; distant terrain stays bounded streaming.

Renderer integration is pinned to Three 0.186. It observes the real primary init and built-in WebGL2 fallback, uses a guarded `_getFallback` adapter to prevent late canceled fallback, and handles late init settlement before disposal. Narrow Three error capture is needed because asynchronous GPU pipeline failures can be logged while compileAsync resolves. Those paths are model-tested; real GPU driver / device-loss, rendered appearance, touch, first-entry responsiveness and performance remain unverified.
