# AXIOM system workbench

A standalone, disposable workspace for the actual regional water, freight and food models, separately or in one integrated **Settlement** scenario. It does not start the full game, create a multiplayer session, or read/write campaign storage. The current food implementation is available for local workbench experiments; its inherited release-review hold is still in force.

## Open and use

With the normal local Vite server running, open `/system-workbench.html` directly. The full game also exposes **Settings → Advanced → System workbench** in a separate tab, carrying only the current seed. No active save or campaign object is passed.

1. Choose a repeatable unsigned seed, system, rainfall model, freight travel model and local target. **Settlement** has one target, **Alder–Pine settlement** (index 0); it begins empty at zero active seconds. Fresh browser scenarios use **Regional** rainfall and freight travel; choose **Legacy** for the corresponding historical behavior
2. Choose **One route**, **One settlement**, or **One chunk**, then **Generate / reset**
3. Start paused; use **Step 0.25 s**, **+1 second**, **+60 seconds**, or **Run** at 1×, 10× or 60×. Pause remains available during a pending batch. Hidden tabs pause and never catch up. A scenario stops after one active hour
4. For Trade and Settlement with Regional travel, inspect the read-only **Freight travel** card: each route’s wetness, wet/drying/dry condition, current movement speed and repair-aware arrival estimate. For Water, Farming and Settlement, inspect the read-only **Local rainfall** card: seeded phase, intensity, active drought time and time until the expected rainfall-front change. Inspect inventory, current job and cause, numbered people, exact world coordinates, actual carried goods and conservation errors. Settlement also shows separate causes for both freight routes, its collector and its farm. Explicit production-start, repair, construction, reserve-withdrawal, material-delivery and crop-tending buttons use the ordinary production commands
5. **Check save round-trip** verifies only the disposable current state using strict production serialization/parsing. Later state changes invalidate that check
6. **Export report + replay** saves the seed, bounded action journal, 10-second state fingerprints, final ledgers, selected-geometry fingerprint and numerical checks. Load that file to recreate the seed and command timeline, compare the result, and locate the earliest sampled difference. This never imports an arbitrary campaign snapshot

Existing campaigns keep their original rainfall model. The rainfall selector resets only a fresh disposable scenario; it never upgrades a progressed save. Choose **Water + Regional** and advance the clock to observe rain, drought, stored-water depletion and the production model's shortage causes. Farming reads the weather at its source collector, including prerequisite setup time; its displayed scenario clock still starts at zero. Settlement reads its collector’s weather with no prerequisite-clock offset: every production clock starts at zero and advances together. Trade retains the rainfall choice for its disposable supply ledger but has no collector-rainfall card. Regional freight independently samples the shared seeded weather at a fixed midpoint of its corridor. That bounded exposure applies to the entire existing path: wet-road speed ranges from 0.9 to 1.8 m/s, and each completed 30 dry active seconds removes a quarter of wetness. It is not point-by-point terrain moisture. The freight selector applies to the prerequisite freight in Farming as well. It does not change route geometry, source throughput, carrying capacity, unloading, store construction or crop production. Pauses and hidden-tab time never dry roads. Existing version-1 freight retains constant-speed travel. A damaged road remains a repair prerequisite: its delivery ETA is unavailable until repaired, rather than showing an impossible arrival time. Regional weather uses a bounded, seeded 2,500-active-second repeating season, including a long drought and recovery rain; it does not advance while paused. A 2,500-second Water run exposes a whole season without changing production speed.

Changing inputs marks the displayed result as old and pauses the clock until Generate / reset. Reset cancels the old worker. File reads and worker responses from replaced scenarios are ignored. Back/Forward cache restoration keeps the paused scenario; a normal page reload starts fresh, so export valuable work first.

## Scenario setup and boundaries

- **Trade:** Starts the selected finite source through its accepted production action. The existing freight obstruction remains until you repair it. Deliveries require actual route distance and unloading; stores require delivered stock and construction time. Reserve withdrawal stays finite
- **Water:** Earns the selected collector's exact wood/stone cost through existing reachable gathering fixtures, delivers it and starts construction. Residents complete it, collect rainfall and drink autonomously
- **Settlement:** Starts two existing freight routes and stores, one collector and one farm unstarted. All production clocks start at zero, and no fixture materials, water or food are granted. Earn freight, repair obstructions, construct stores, withdraw finite reserves and deliver the collector’s wood/stone prerequisites before building it. The farm can start as soon as its own freight store is ready, while crop growth waits for new collector overflow. Farm start itself grants four separately conserved starter meals through the existing production reducer; those are not a setup gift or harvested food. Harvested-food consumption requires `meals > 4`. See [Regional settlement](REGIONAL-SETTLEMENT.md) for the command chain and evidence boundaries
- **Food:** Reuses the existing production lab fixture to earn the three old freight stores and their collectors before enabling food. Setup can take several seconds in the background worker. Its active prerequisite time is displayed separately. Only the selected farm starts; new overflow, two reusable seeds, crop work, carried food and meals use the production reducers. Four explicitly accounted starter meals are not harvested food. Existing discarded overflow is not reclaimed

Setup approach positions are model placements, not an executed player-controller walk. The integrated scenario uses actual production actor positions and conserved ledgers. No stock, water, production speed or actor-position simulation is reimplemented. The sandbox only selects inputs, schedules quarter-second production ticks, records commands and projects results.

One-route view renders the selected existing path points without generating terrain chunks; for Settlement it includes both freight routes and the collector/farm paths. One-chunk view compiles exactly the selected production chunk. One-settlement view shows a 64 m square, with at most four intersecting chunks. Regional plan metadata and prerequisite ledgers remain bounded production dependencies; this is not a separate whole-region renderer.

The plan view draws actual generated terrain/roads/structures and authoritative actor coordinates. It is a numerical schematic, not a collision or rendered-quality test. The **Animations & graphics** surface lazily embeds the existing `/visual-review.html` production inspector, retaining its animation timelines, fixed poses, captures and manual review. Returning to systems unloads that graphics scene. It can also be opened separately.

## Headless workflow

Use Node 22.23.0 and the already-installed project dependencies. The workbench command itself does not download packages, start a server or use a browser.

```sh
node --experimental-strip-types scripts/system-workbench.mts --help
node --experimental-strip-types scripts/system-workbench.mts --system trade --seed 73129 --seconds 1800 --assist --reload --output trade.json
node --experimental-strip-types scripts/system-workbench.mts --system settlement --seed 73129 --index 0 --rainfall regional --travel regional --seconds 3600 --assist --reload --output settlement.json
node --experimental-strip-types scripts/system-workbench.mts --system water --rainfall regional --index 0 --seconds 2500 --view settlement --geometry collector-plan.json --output water.json
node --experimental-strip-types scripts/system-workbench.mts --system food --index 1 --seconds 600 --assist --reload --output farm.json
node --experimental-strip-types scripts/system-workbench.mts --system water --rainfall legacy --travel legacy --seconds 60 --output historical-water.json
node --experimental-strip-types scripts/system-workbench.mts --replay farm.json
node --experimental-strip-types --test tests/system-workbench*.test.ts
```

The CLI defaults to `--rainfall regional --travel regional`. `--rainfall legacy` selects historical collectors; `--travel legacy` selects historical constant-speed freight. The choices are independent, and invalid values are rejected. JSON console output identifies both choices and includes local weather for Water, Farming and Settlement, per-route travel conditions and repair-aware ETA for Regional Trade/Settlement, plus per-system causes for Settlement.

`--assist` issues eligible production commands once per simulated second, recording each accepted action at the actual current production clock. In Settlement it starts both freight sources, repairs routes once carriers are actually blocked, builds stores, withdraws required finite material reserves, delivers collector materials (including partial deliveries), builds the collector, starts the farm once its local store is ready and tends eligible crops. This work can overlap; the farm need not wait for collector completion, but growing crops need new overflow. The separate Trade/Food scenarios retain their repair/build/tend behavior. It does not change production speeds or create resources. Without it, CLI freight can correctly remain blocked while waiting for repair. A replay takes all simulation settings from the report; simulation overrides are rejected. Exit 0 means the requested numerical run/replay passed, 1 means a failed balance, round-trip or mismatch, and 2 means invalid input. Fingerprints are deterministic comparison aids, not cryptographic authentication.

Settlement reports use version 2 and explicitly identify each action’s target; they never infer a target from an ambiguous command name. Separate-system reports remain version 1. Old reports with no travel field select version-1 freight. Reports with neither optional field retain their original config structure, production ledgers, snapshots and state fingerprints; old Settlement reports with regional rainfall and omitted travel retain the same historical freight. The internal `DEFAULT_WORKBENCH_CONFIG` stays legacy for that compatibility; browser and CLI creation explicitly choose regional rainfall and travel. A config value of `legacy` normalizes to an absent field. Weather and freight conditions are optional derived snapshot projections, excluded from replay fingerprints, and never trusted as a source of state on import. Imported reports restore their own rainfall and travel choices. Legacy reports omit the new freight projection, preserving their historical shape.

After the ordinary local build, `node --experimental-strip-types scripts/verify-system-workbench-build.mts /tmp/workbench-build.json` invokes the compiled server's asset handler in-process and executes the actual emitted workbench worker through a Node worker-thread adapter. It checks served bytes and parity with the source model for all four systems; it makes no network requests.

## Verification and release limits

For repeatable ordinary-duration seed coverage, use the [procedural scenario matrix](PROCEDURAL-SCENARIO-MATRIX.md). Its CLI selects seeds/cases/budget, defaults to 27 cases across 20 deterministic seeds, records shortages without inventing completion, and saves bounded replay/failure evidence. The inherited terminal-clock hold is unchanged.

Executable tests cover settlement selection and reset, empty zero-clock setup, target-specific action forwarding, per-system causes, integrated report/replay and historical pre-weather fingerprint parity, independent rainfall/travel selection and validation, historical travel fingerprint compatibility, regional freight partitioning, blocked delivery ETA, read-only travel cards, stale travel edits and import restoration, regional weather partitioning/reload/replay, read-only weather projection, stale rainfall edits and import restoration, deterministic generation/partitioning, water use, physical-time freight, conserved food and meals, rejected commands, bounded replay input, expected-state mismatch, CLI exit codes, worker failures, repeated clicks, pause during work, reset races, stale imports, graphics teardown, Back/Forward restoration and save-check expiry.

Local TypeScript, production build, aggregate tests and compiled-workbench evidence are checked against the final source revision separately. Numerical and non-rendering DOM tests do not establish browser appearance, actual graphics execution, phone ergonomics or device performance. Previously denied browser/network/review routes remain untouched. This is a local implementation checkpoint; the inherited food release gate remains blocked, and neither the live Site nor the released source archive is replaced by this work.

## Optional emergency irrigation

The separate Farming scenario can opt into Food v2 through Emergency irrigation → Optional Food v2. It earns one real generated canister during its explicitly labeled prerequisite setup; only the manual action spends it. This uses report v3. Existing choices and the zero-start Settlement scenario retain their old models and fingerprints. See [one-time irrigation](REGIONAL-EMERGENCY-IRRIGATION.md) for access, limits, accounting and ordinary-clock verification.
